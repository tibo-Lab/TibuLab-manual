TibuLab Installation & Setup

For the hospital's IT person or the lab owner. It shows how to install TibuLab on the hospital's own computer, connect the other PCs, phones and TVs, and link the lab analysers, the X-ray console and the ICU monitors. The pictures are simple drawings, so you do not need to be technical.

TibuLab is installed on one PC only: the Main PC. Every other PC, tablet, phone and TV opens TibuLab in a web browser (Chrome or Edge). Nothing is installed on them, except the small TibuLab Print Helper on PCs that have a patient TV.

1. InstallThe Main PC, about 10 minutes 2. First setupPassword, hospital, locations, staff 3. Lab analysersCable, settings, test codes, test run 4. X-rayWorklist, images, Fuji CR console 5. ICU monitorsLive vitals, alarms, escalation 6. Daily careBackups, updates, problems
Tip: staff who only use TibuLab (reception, lab, radiology, cash, HR) should read the User Manual. This guide is for setting it up.

The hospital network

One Main PC holds all the data. Everything else talks to it over the hospital's own network. The internet is only needed for the cloud copy, the licence check, SMS and updates.

Four network rules

  1. Fixed IP for the Main PC. In the router, reserve one address for the Main PC (for example 192.168.1.10). If the IP changes, every bookmark, TV, analyser and X-ray console loses the link.
  2. Same network. All PCs, phones, TVs, analysers, the X-ray console and the ICU station must be on the same hospital network (same router or switch). Use a cable for the Main PC.
  3. Everyone opens http://IP:8080, for example http://192.168.1.10:8080.
  4. A UPS on the Main PC, the switch and the router. 30 minutes or more is better. Pulling the power can damage the database.

Keep the Main PC switched on during working hours. If it is off, nobody can use TibuLab. Do not use it for games, downloads or personal work.

Install on the Main PC

File: TibuLab-Main-PC-Setup-<version>.exe

About 10 minutes, plus a few minutes for the first start. Run it on the Main PC only.

  1. Copy the setup file to the Main PCYou

    TibuLab-Main-PC-Setup-<version>.exe. Right-click it and choose Run as administrator.

  2. Welcome and licence pagesYou

    Click Next and accept the licence agreement.

  3. Install folderYou

    Keep the default: C:\Program Files\TibuLab. This holds the program only.

  4. Lab data folderImportant

    The default is C:\TibuLabData. Choose another drive if you have one, for example D:\TibuLabData. It holds the database, backups, uploaded files and logs. An update or uninstall never deletes this folder.

  5. InstallYou

    Click Install, then Finish with Start TibuLab now ticked.

  6. The installer does three things by itselfAutomatic

    Opens port 8080 in the Windows firewall for private and domain networks only (never public Wi-Fi). Makes TibuLab start with Windows. Adds a TibuLab shortcut to the desktop and Start menu.

  7. First start: a few minutesAutomatic

    The tray icon (next to the clock) is amber and shows the step: "Preparing the data folder…", "Creating the database (first start)…", "Creating the lab's tables (first start)…", "Setting up the lab (first start, a few minutes)…", "Starting the web server…".

  8. Green: TibuLab is runningDone

    Right-click the tray icon, choose First sign-in details, then Open TibuLab. Continue with First sign-in.

TibuLab brings everything it needs, so nothing else is installed on the PC:

Other PCs, phones and tablets

  1. On the Main PC, read the link in the tray menu: Other PCs / phones: http://IP:8080.
  2. On every other PC, open that link in Chrome or Edge. Add it to the bookmarks bar.
  3. On phones and tablets (on the hospital Wi-Fi), open the same link and choose Add to Home screen.
  4. Each person signs in with their own email and password. Their role decides which screens they see (see Staff, roles and portals).
The link works only inside the hospital network. Phones on mobile data cannot reach it.

First sign-in

  1. Right-click the tray icon and choose First sign-in details. Notepad shows the link, the email (admin@tibulab.local) and a one-time password of 12 letters and numbers.
  2. Choose Open TibuLab and sign in with them.
  3. Go to Settings › Users. Open your user, give a real email and a new password, and save.
  4. Delete the file FIRST-LOGIN.txt from the data folder. After that, the tray says "The first sign-in details were already removed".
Anyone who reads FIRST-LOGIN.txt can sign in as the owner. Change the password and delete the file on the first day.

Hospital, locations and counters

Do these once, in this order, before the first patient. TibuLab is set up as Business → Locations (branches) → labs, pharmacies, radiology rooms and counters inside each location.

  1. Settings › Business: hospital name, phone, address, NTN, licence number, logo, header and footer text.
  2. Settings › Locations: one per building or branch. Open a location to add its labs (on each floor), pharmacies, radiology rooms and counters.
  3. Counters (reception, cash, sample collection, pharmacy) are added on the location page, or in Billing › Cash Registers. Money is taken only on an open counter.
  4. Settings › Report Layout and Signatures: letterhead, paper size and the pathologist's / radiologist's signature.
  5. Settings › Numbering: the start numbers of bills and receipts (only if you continue from an old system).

The User Manual has pictures of these screens: First-time setup.

Doctors and the duty roster

One record per doctor

A doctor is an HR employee with the Doctor section filled in. Add doctors in Billing › Referring Doctors (outside doctors) or OPD › Setup › Doctors (staff and visiting consultants). Both open the same employee form.

  1. Add the doctor (name, PMDC no., speciality, fees and shares).
  2. For a doctor who signs in, make a user with the role doctor in Settings › Users, and link that user account on the doctor's employee form.

Duty roster for nurses and doctors

Duty roster › Monthly roster

Set up the roster units in Duty roster › Units (for example ICU, Ward 2), then fill the Monthly roster. On duty now shows who is working. ICU alarms that nobody answers go to the staff on duty now (see ICU monitors), so keep the roster up to date.

Licence

http://localhost:8080/licence on the Main PC

The licence is a key from TibuLab, like TL-XXXX-XXXX-XXXX. It is activated once on the Main PC.

  1. When TibuLab asks, type the licence key and click activate. The Main PC must be online for this.
  2. TibuLab cloud sends back a signed licence token. It is tied to this PC: copying it to another PC does not work.
  3. After that the PC works offline on the saved token. The scheduler checks every hour whether a check is due, and asks the cloud about once a day.
  4. After you pay a renewal, open the licence page and use the check-now button, so it unlocks at once without waiting for the daily check.

The three states

StateWhat staff seeWhat to do
okNothing special.Nothing.
warnA banner: subscription ends soon, expired (renew within N days), or no internet for N days.Renew, or connect the Main PC to the internet.
readonlyOnly viewing, reports and sign-in work. No new bills or results.Renew, or connect to the internet. It unlocks straight away after the check.
Not activated / on holdThe activation page, or "account is on hold".Enter the key, or call TibuLab support.
A renewal or plan change arrives by itself with the next daily check, even if nobody opens a page.

Cloud copy and sync

Settings › Devices & Licence (page "Devices & sync")

All work is done on the Main PC. TibuLab also keeps a read-only copy in TibuLab cloud. Nothing can be typed into the cloud copy.

  • What goes: every changed record. Labs on the Main PC send the full verified results, so the portal and other hospitals see the values, not only a summary.
  • Other hospitals' doctors see a patient's history only when TibuLab is sure it is the same person. The patient can switch sharing off. Every look is written in a log, and the patient can see who looked (patient portal › Security).
  • Check it: Settings › Devices & Licence shows this installation's link to the cloud, Waiting to sync and Failed items. Failed items are tried again on every sync.
  • Sync runs only when the Main PC is linked to the cloud, by its licence or by a device token. TibuLab support does this.

Lab analysers (machines)

Laboratory › Machines › Analyzers

The Device Hub on the Main PC talks to the analysers. Results come straight into TibuLab, with no typing. It works without internet.

Three ways to connect a machine

Connect a machine, step by step

  1. Switch on the Device Hub (once). Open Laboratory › Machines › Analyzer Status. If it says "Device Hub is not running on the lab server", ask TibuLab support to switch it on. They add the line TIBULAB_DEVICE_HUB=true to the .env file in the data folder and use Restart services. The scheduler then keeps the hub running.
  2. Cable. Connect the analyser as in the drawing above. Give a network analyser (or the adapter) a fixed IP, for example 192.168.1.50.
  3. Add the analyser in TibuLab. Laboratory › Machines › Analyzers › Add. Pick the Model preset first (for example Sysmex XN, Sysmex XP-100, Mindray BC-5000, Mindray BS-200, Roche c311, Erba XL-200, Maglumi, Bio-Rad D-10…). It fills the protocol, connection and serial settings. Then give the code, name, location and lab section.
  4. TibuLab's settings. Check the Protocol (ASTM, LIS2-A2, HL7, CSV file, Sysmex K) and the Connection:
    ConnectionFill in
    TCP – machine connectsTCP port the Main PC listens on (e.g. 5001). Optional: the machine's IP, so only it may connect. Allow this port in the Windows Firewall of the Main PC.
    TCP – we connectThe analyser's IP address and TCP port. No firewall rule needed.
    Serial (COM / USB)The adapter's IP address and TCP port (often 4001), and the baud rate, data bits, parity, stop bits of the analyser.
    Shared folderThe Folder path as the Main PC sees it. Set the file layout under Hub options on the Mappings screen.
  5. The machine's host settings. On the analyser, open its Host / LIS / Communication menu (the preset's "How to connect this model" box tells you where). Set the same protocol, the host IP = the Main PC's fixed IP and the same port. For serial, the speed and settings must match on both sides. If the analyser can ask for tests by barcode (host query), switch that on, and switch on Answer host queries (send ordered tests) in TibuLab.
  6. Is it online? Analyzer Status shows each machine: Online, Waiting for analyzer, Connecting, Offline or Error, with the last message and errors today.
  7. Tests on this machine. In the Analyzers list, use Tests on this machine on the row. Link each test with the code the analyser orders it by (main or backup machine).
  8. Map the result codes. Open Analyzer Status › Mappings. Each machine code (WBC, HGB, GLU…) is linked to a TibuLab parameter. Use Apply suggested mappings from the preset, then check them. A unit change is done with value × multiplier + offset.
  9. Test run. Bill a test patient, collect the sample, print the label and run it on the analyser. Then:
    • Laboratory › Machines › Machine Message Log shows every message (Received, Processed, Error) with Raw and Parsed views.
    • Unmapped codes seen on the Mappings screen lists codes not mapped yet. Map them: the results of the last 14 days are taken in again. Replay in the log parses a message again after a fix.
    • Compare the values on Result Entry with the analyser's own printout. Go live only when they match.
Safety: machine values never go on a report by themselves. They wait on Result Entry until the technician checks and saves them, and the pathologist verifies them.

Other systems (HL7 out)

TibuLab can also send HL7 v2 messages (patients, admissions, OPD visits, lab orders) to another hospital system. They are queued and sent every minute. Ask TibuLab support to set up such a link.

Sample to report: the full flow

The barcode on the tube is the sample ID. It joins the patient, the order, the analyser result and the report.

  1. 1. OrderReception

    New Bill: the patient is registered and the tests are billed. TibuLab makes the lab order.

  2. 2. Barcode labelSample room

    Sample Collection: the collector takes the sample and prints the barcode label (one per tube).

  3. 3. TubeSample room

    The label goes on the tube. The tube goes to the lab (Sample Dispatch for another lab).

  4. 4. The machine reads the barcodeAnalyser

    The tube goes into the analyser. Its reader scans the barcode.

  5. Two-way machine

    It asks TibuLab "which tests for this barcode?" (host query). TibuLab answers with the ordered tests.

    One-way machine

    It does not ask. The technician scans or types the TibuLab barcode as the Sample No. on the analyser.

  6. 5. Result comes backDevice Hub

    The analyser sends the results. The Device Hub finds the order by the barcode and turns the machine codes into TibuLab parameters.

  7. 6. Technician checksTechnician

    Result Entry shows the values "from <machine>". Check, change if needed, then Save. A wrong value can be rejected.

  8. 7. Pathologist verifiesPathologist

    Verification: the pathologist verifies and signs. Critical values go to Critical Results.

  9. 8. ReportPatient

    Printed or shared. With the cloud link, the verified report also reaches the patient portal.

Reception / sample roomAnalyser and Device HubTechnicianPathologist

X-ray and radiology

Radiology › Setup › PACS · Image folders · Rooms & Machines

TibuLab connects to the console PC of the X-ray (the PC where the radiographer sees the image), not to the X-ray tube itself.

Words you will see

WordMeaning
Accession numberThe number TibuLab gives each billed exam. It travels with the images and joins them to the right exam.
Modality worklistThe patient list TibuLab sends to the machine: name, MRN, exam and accession. The radiographer picks the patient instead of typing. An exam is listed while it is scheduled (yesterday to 7 days ahead), arrived or being scanned, and removed once scanned, cancelled or no-show.
PACSThe image store. TibuLab works with Orthanc (free PACS software) on the Main PC or another PC. The TibuLab installer does not include it yet: ask TibuLab support to set it up.
AE titleThe DICOM name of a machine or of the PACS, up to 16 letters or numbers (for example TIBUPACS). Each machine needs its own.
Unmatched studyImages that came in but could not be joined to an exam. They wait in Radiology › Unmatched Studies.

The X-ray flow

  1. 1. Patient and billReception

    New Bill: the X-ray exam is billed. TibuLab gives it an accession number.

  2. 2. Radiology WorklistRadiographer

    The exam appears on the radiographer's list. They mark the patient arrived and start.

  3. 3. Patient list to the machineWorklist

    If the worklist is on and the console supports it, the console shows the patient with the accession number. No typing.

  4. 4. Console makes the imageX-ray console

    The radiographer takes the X-ray. The console shows the image and can print the film as before. Mark Scan done.

  5. 5. Image to TibuLabPACS / folder / upload

    The images reach TibuLab (see the four ways below). They join the exam by the accession number by themselves. No match: Unmatched Studies.

  6. 6. Radiologist reportRadiologist

    Radiology › Reporting: open the images, write the report from a template, verify and sign.

  7. 7. PrintPatient

    The report is printed with the key images that were ticked. The patient takes the film and the report.

Drawing 4. The X-ray flow: patient → bill → worklist → console → image → TibuLab → radiologist report → print.

Set up the PACS (DICOM)

  1. Radiology › Setup › PACS › Add PACS: Name, PACS software, PACS AE title, PACS IP / host (the Main PC's IP), DICOM port (Orthanc's default is 4242), Web API address (e.g. http://192.168.1.10:8042) with its user:password, and the Viewer link.
  2. For the worklist: the Worklist folder and tick Send patient list (modality worklist) to machines.
  3. Delete images after (days): empty keeps them forever. Click Test connection.
  4. For each room / machine (Rooms & Machines and the Machines list on the PACS page): the Machine AE title, Machine IP and Port exactly as set on the machine, Sends images to, Reads patient list (worklist).
  5. On the machine or console: add the PACS as a DICOM destination with the same AE title, IP and port. Allow the DICOM port in the Windows Firewall of the PACS PC.

Machines without DICOM: image folders

Radiology › Setup › Image folders

For machines that save JPG, PDF or DICOM files to a folder (ultrasound, ECG, some X-ray consoles). Works on the Main PC only, not in the cloud.

  1. Share the machine's export folder on the network.
  2. Add an image folder: Name, Folder path as the Main PC sees it (for example D:\ecg\out or \\US-PC\export), Files to take (*.jpg,*.pdf,*.dcm), After import (move to "imported", delete, or leave) and Scan every (seconds).
  3. The accession number must be in the file: in the DICOM tag, the file name or the folder name. Other files wait in Unmatched Studies.

Upload by hand

On any exam, Add images / files takes JPG, PNG, PDF or DICOM files (a photo of the film, a scanned page). Tick Key image (printed on the report) on the pictures that should be printed on the report.

Unmatched studies

Radiology › Unmatched Studies lists images with no exam (typed wrongly on the console, or no accession). Open one and use Link to exam, or Ignore it (with a reason) if it is not a patient exam.

ICU monitors

ICU Monitoring › Live monitor · Setup

Bedside monitors send vitals to their central station (Mindray, Philips, GE). The central station sends them to TibuLab. Doctors and nurses then see every ICU bed live, on a PC or phone.

Remote view only. TibuLab does not replace the bedside monitor alarms. Always respond to the bedside alarm. Values can be late or missing when the network or the central station is down.

How monitor data gets in

WayHow
Device Hub, station connectsThe central station sends HL7 (PCD-01) to the Main PC's IP and a port (e.g. 4601). Allow that port in the Windows Firewall. Optional: only the station's IP may connect.
Device Hub, hub connectsFor gateways that act as an HL7 server: TibuLab connects to the gateway's IP and port.
HTTPS with a tokenThe gateway posts HL7 to TibuLab with a station token. The token is shown only once when it is made.
By handNo monitor link: nurses enter vitals in the Nurse portal › Vitals.

Set up

  1. The Device Hub must be on (see Lab analysers, step 1).
  2. ICU Monitoring › Setup › Central stations: code, name, vendor, model, connection, host, port.
  3. Devices: each monitor, and the bed it stands at. The patient is taken from the bed's current admission.
  4. Alarm limits: the low / high limits and how long a value must stay out before it is an alarm (default 30 seconds).
  5. Code map: the station's codes to TibuLab's (HR, SpO₂, NIBP, RR, Temp…).
  6. Settings: escalate after N minutes (default 5), the ICU on-call users, and SMS on escalation (if the hospital has SMS).

Alarm and escalation

  1. Monitor readingMonitor → station → TibuLab

    Live values appear on the bed tile.

  2. Out of range: PendingTibuLab

    One bad reading (movement, probe off) is not an alarm. It must stay out for the set time.

  3. AlarmICU screen

    The tile turns red and the browser plays an alarm tone.

  4. Acknowledged in time

    A nurse or doctor clicks Acknowledge and writes what was done (for example "Seen, O₂ increased to 6 L, doctor informed"). It does not ring again.

    Nobody acknowledged in 5 minutes

    Escalation: the staff on duty now in the duty roster for that ward (else the ICU on-call list in Settings), plus the patient's consultant, get the bell, and an SMS if switched on.

  5. Back in rangeResolved

    The alert closes. Every alert stays in the bed's history.

Drawing 5. ICU monitor → alarm → escalation.

Auto-charting: every hour (default) TibuLab proposes the monitor readings for the nursing chart. Nothing goes into the chart until a nurse validates it (ICU Monitoring › Auto-charting).

Printers and labels

Receipts, tube barcode labels and reports print from the browser on each counter PC.

  1. Install the printer on the counter PC (USB or network) with its Windows driver: receipt printer (80 mm or 58 mm), label printer, and an A4/A5 printer for reports.
  2. Choose the paper size and design in TibuLab: Settings › Print designs, Barcode labels (with a test print) and Report Layout.
  3. Print once from Chrome and choose the right printer. Chrome remembers the last printer.

TibuLab Print Helper

File: TibuLab-Print-Helper-<version>.exe

A small tray program for counter and doctor PCs. Today it opens the patient TV on this PC's second screen (see Queue and doctor TVs). It starts with Windows. Its tray menu: Show TV again, Stop TV on this PC, Quit TibuLab Print.

Not available yet: printing straight to a chosen printer through the Print Helper (receipts, labels and reports with no print box). Until then, use browser printing as above.

Queue and doctor TVs

Settings › TV screens

TV screens show the tokens: a doctor's door, a waiting hall with several doctors, or the lab hall (sample collection calls, reports ready). They can call in English and Urdu, and show pictures and videos when the queue is quiet.

A smart TV or a TV with its own small PC: pairing

  1. Add the screen in Settings › TV screens (type, doctor, language, voice).
  2. Click Pair TV and open that link on the TV once, full screen (F11). It keeps working without a login.
  3. Pairing again stops the old TV.

A TV on a PC's HDMI second screen: "Show on this PC's TV"

  1. Connect the TV to the PC with an HDMI cable. Press Windows + P and choose Extend.
  2. Install the TibuLab Print Helper on that PC.
  3. In TibuLab click Show on this PC's TV (in Settings › TV screens, or the doctor's TV button on his OPD screen).
  4. The TV shows the queue, with sound. It opens by itself every time the PC starts. Nothing else to do. Stop TV on this PC turns it off.
Without the Print Helper it still works in Chrome or Edge, but the TV opens with your first click in TibuLab each day, and you must click once on the TV for sound. Allow pop-ups for TibuLab if the browser blocks the TV window.

Backups

Admin › System health
  • Automatic: every night at 02:30 TibuLab backs up the whole database.
  • Where: <data folder>\storage\backups\tibulab\, one compressed file per backup. Backups older than 14 days are removed.
  • Check: Admin › System health shows the last backup, its folder, errors and the latest files. Back up now makes one at once.
Copy backups off the Main PC. A backup on the same disk is lost if the disk dies or the PC is stolen. Every week, copy the newest backup file to a USB drive or another PC, and keep one copy outside the hospital. TibuLab support can also set a second copy folder (another disk or a network share).

Restore is done by TibuLab support. Never copy database files by hand while TibuLab is running.

Moving to a new PC: install TibuLab on the new PC, choose Quit on the old one, copy the whole data folder across, then start TibuLab on the new PC. The licence must be activated again on the new PC.

Updates

  1. Back up first: Admin › System health › Back up now. Do updates after working hours.
  2. Run the new TibuLab-Main-PC-Setup-<version>.exe over the old one, as administrator. It finds the same install and data folders by itself.
  3. The setup stops TibuLab (the database shuts down cleanly) and replaces the program and its runtime. The data folder and the settings are kept.
  4. On the next start the tray shows "Updating the database…". When the dot is green, the update is done.
Not available yet: automatic updates from the tray (an "update ready" notice, installing at night, the automatic backup and roll-back if an update fails, and update from a USB file). Today an update is the new setup file run by hand, with a backup taken by you first.

The Print Helper is updated the same way: run its new setup file on each PC.

Problems and fixes

ProblemWhat to do
Other PCs can't open the linkSame network? Is the Main PC's IP still the same (fixed IP)? Is the Windows network set to Private (the firewall rule is for private and domain networks only)?
"Starting…" for more than 10 minutesTray › Restart services. Still stuck: send the logs folder to support.
Red dot, "keeps stopping"Tray › Restart services. Check that the disk is not full.
"Port 8080 is used by another program"Close the other program (another web server, Skype…), or restart the PC, then Restart services.
Disk fullThe database stops when the disk is full. Free space on the data drive (and on C:), then Restart services.
Banner: subscription ends / no internetRenew, or connect the Main PC to the internet. See Licence.
Read-only: can't make billsThe licence is past the grace days or offline too long. Renew or connect, then use check-now on the licence page.
Many items "Waiting to sync"The Main PC is offline. It catches up by itself when the internet is back.
"Device Hub is not running"Ask support to switch the Device Hub on (data folder .env), then Restart services.
Analyser OfflineCable, the analyser's IP, the host IP and port on the analyser, the firewall rule for that port on the Main PC.
Results don't arrive on Result EntryMachine Message Log: is there an Error? Unmapped code: map it. Wrong barcode on the analyser: fix it, then Replay.
X-ray images don't arriveThe AE title, IP and port on the console must match the PACS page. Firewall rule for the DICOM port. Test connection on Radiology › Setup › PACS.
Images in Unmatched StudiesWrong or missing accession number. Link them to the exam by hand.
ICU tile shows "no data"No reading for a minute: check the central station, its cable, and the station's status in ICU setup.
TV doesn't open on the HDMI screenWindows + P › Extend. Use Chrome or Edge. Allow pop-ups. Is the Print Helper running in the tray?
Forgot the owner passwordAnother admin resets it in Settings › Users, or call TibuLab support.
